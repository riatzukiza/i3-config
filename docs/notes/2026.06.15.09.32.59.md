## Facts

clj-kondo merges configuration from home config, then any directories listed in `:config-paths`, then the project’s own `.clj-kondo/config.edn`, then env/CLI/local overrides. That means a shared package works best as a base layer, while each app/package can still override locally. 
clj-kondo also documents config exports under `clj-kondo.exports/<org>/<libname>/`, and those exports can be activated locally with `:config-paths`. This is intended for reusable library configs, which maps well to “shared lint package in a monorepo.” 
## Recommended layout

In a pnpm monorepo, I would use a package dedicated to lint config, for example:

```text
packages/
  clj-kondo-config/
    package.json
    clj-kondo.exports/
      your-org/
        shared-kondo/
          config.edn
          clj_kondo/
            your_macros.clj
  web-app/
    .clj-kondo/
      config.edn
  admin-app/
    .clj-kondo/
      config.edn
pnpm-workspace.yaml
```

This layout follows clj-kondo’s export/import shape, so the shared package behaves like a reusable library config instead of a random copied folder. It also keeps hooks and `:lint-as` rules colocated with the shared lint contract. 
## Per-package config

Inside each package that wants the shared rules, add a local `.clj-kondo/config.edn` like this:

```clojure
{:config-paths ["../../clj-kondo-config/clj-kondo.exports/your-org/shared-kondo"]

 :linters
 {:missing-docstring {:level :warning}
  :unused-value {:level :warning}
  :shadowed-var {:level :warning}
  :used-underscored-binding {:level :warning}
  :warn-on-reflection {:level :warning}
  :unsorted-required-namespaces {:level :warning}
  :refer {:level :warning}}}
```

` :config-paths` is the key mechanism here: clj-kondo explicitly supports listing directories that provide additional config, and those directories are merged before the local project config. That gives you one shared baseline plus package-specific deltas. 
## Shared package contents

Your shared package’s exported config might look like this:

```clojure
;; packages/clj-kondo-config/clj-kondo.exports/your-org/shared-kondo/config.edn
{:lint-as
 {your.dsl/defview clojure.core/defn}

 :hooks
 {:analyze-call
  {your.dsl/route your-org.shared-kondo.hooks/route}}

 :linters
 {:missing-docstring {:level :warning}
  :unused-value {:level :warning}
  :shadowed-var {:level :warning}
  :used-underscored-binding {:level :warning}
  :unsorted-required-namespaces {:level :warning}
  :refer {:level :warning}}}
```

If you ship custom hooks, keep them under the exported tree as documented by clj-kondo’s sample export structure. That way the consumer package only needs the one `:config-paths` entry. 
## Monorepo caveat

For CLI usage, clj-kondo resolves project config based on the current working directory, and the maintainer explicitly recommends either linting each subproject from its own directory or passing `--config-dir` manually in monorepos. So for CI, pre-commit, or pnpm scripts, do not assume one root invocation will always infer the right package config. 
Examples:

```json
{
  "scripts": {
    "lint:kondo": "clj-kondo --lint src:test --config-dir .clj-kondo"
  }
}
```

Or from repo root:

```bash
pnpm --filter web-app exec clj-kondo --lint src:test --config-dir .clj-kondo
pnpm --filter admin-app exec clj-kondo --lint src:test --config-dir .clj-kondo
```

That pattern matches the documented monorepo guidance from the GitHub issue: run per project, or set `--config-dir` yourself. 
## Interpretation

There are really **three** viable patterns here:

| Pattern | When to use it | Tradeoff |
|---|---|---|
| `:config-paths` to a shared workspace package | Best default for pnpm monorepos. | Simple, explicit, easy local overrides.  | `clj-kondo.exports/...` shared package | Best when you also share hooks, macro configs, or want “library-style” reuse. | Slightly more ceremony, but cleanest architecture.  | `--config-dir` in per-package scripts | Best for CI, pre-commit, and editor/CLI consistency in monorepos. | Operational, not compositional; you still usually want local config files.  
My recommendation: use **both** exported shared config and per-package `.clj-kondo/config.edn` files. The export package defines the common law; the local package config defines package-specific contracts. 
## Concrete starter

Here is the smallest version I’d ship first.

**1. Shared package**

```text
packages/clj-kondo-config/clj-kondo.exports/acme/shared/config.edn
```

```clojure
{:linters
 {:missing-docstring {:level :warning}
  :unused-value {:level :warning}
  :shadowed-var {:level :warning}
  :used-underscored-binding {:level :warning}
  :unsorted-required-namespaces {:level :warning}
  :refer {:level :warning}}}
```

**2. Consumer package**

```text
packages/app/.clj-kondo/config.edn
```

```clojure
{:config-paths ["../../clj-kondo-config/clj-kondo.exports/acme/shared"]}
```

**3. Consumer script**

```json
{
  "scripts": {
    "lint:kondo": "clj-kondo --lint src:test --config-dir .clj-kondo"
  }
}
```

That gives you one reusable config package, package-local opt-ins, and deterministic monorepo execution. 

| Path | Role |
|---|---|
| `config.edn` | `:lint-as`, `:linters`, `:hooks` registry — the wiring layer  |
| `hooks/defroute.clj` | Structural hook teaching kondo the `defroute` macro shape  |
| `hooks/promise_chain.clj` | Cross-cutting hook: promise-chain detection, fn-length, complexity, file-length  |

The `imports/` directory is the lock-in detail: clj-kondo writes resolved third-party analysis there when you run `--copy-configs`. You do **not** want that in the shared package. It stays local per package.

## Target layout

The export directory path is the load-path clj-kondo resolves from `:config-paths`. Hooks files must live inside the same subtree as the exported `config.edn` or in a resolvable relative path from it.

```
packages/
  kondo-config/                          ← new pnpm package
    package.json
    clj-kondo.exports/
      open-hax/
        kondo-config/
          config.edn                     ← shared wiring, no imports
          hooks/
            defroute.clj                 ← verbatim from backend
            promise_chain.clj            ← verbatim from backend

  backend/
    package.json
    .clj-kondo/
      config.edn                         ← `:config-paths` + local overrides
      imports/                           ← stays here, per-package

  frontend/   (or any other cljs pkg)
    package.json
    .clj-kondo/
      config.edn
      imports/
```

## Shared `config.edn`

This is your `backend/.clj-kondo/config.edn` minus any backend-specific `:hooks` entries that don't apply elsewhere (like `:defroute` — see note below):

```clojure
;; packages/kondo-config/clj-kondo.exports/open-hax/kondo-config/config.edn
;;
;; Law layer: shared across all CLJS packages in the Knoxx monorepo.
;; Backend-only hooks (defroute) are registered in backend/.clj-kondo/config.edn
;; via :config-paths merge, not here.

{:lint-as
 {shadow.cljs.modern/js-await  clojure.core/let
  shadow.cljs.modern/js-await* clojure.core/let}

 :linters
 {:unresolved-symbol
  {:exclude [js/console js/Promise js/Error js/JSON js/Object
             js/Array js/fetch js/parseInt js/parseFloat js/Boolean
             js/clearTimeout js/setTimeout js/setInterval js/clearInterval
             js/process js/Buffer js/Symbol js/Date js/Math js/Number
             js/String js/Uint8Array js/ArrayBuffer js/TextDecoder
             js/TextEncoder js/structuredClone js/URL js/URLSearchParams
             js/require js/module js/exports js/__dirname js/__filename]}
  :promise-chain/prefer-async-workflow {:level :warning}
  :fn-length/long                     {:level :warning}
  :fn-length/too-long                 {:level :error}
  :file-length/long                   {:level :warning}
  :file-length/too-long               {:level :error}
  :complexity/high                    {:level :warning}
  :complexity/too-complex             {:level :error}
  :discouraged-var
  {shadow.cljs.modern/js-await  {:level :error
                                 :message "js-await is deprecated; use (await ...) inside a ^:async fn."}
   shadow.cljs.modern/js-await* {:level :error
                                 :message "js-await* is deprecated; use (await ...) inside a ^:async fn."}}}

 :hooks
 {:analyze-call
  {cljs.core/ns       hooks.promise-chain/check-ns
   cljs.core/->       hooks.promise-chain/check
   cljs.core/->>      hooks.promise-chain/check
   cljs.core/do       hooks.promise-chain/check
   cljs.core/let      hooks.promise-chain/check
   cljs.core/when     hooks.promise-chain/check
   cljs.core/when-let hooks.promise-chain/check
   cljs.core/if       hooks.promise-chain/check
   cljs.core/defn     hooks.promise-chain/check-defn
   cljs.core/defn-    hooks.promise-chain/check-defn}}}
```

Note the `defroute` hook is intentionally **absent** here because `knoxx.backend.macros/defroute` is a backend-only symbol. Putting it in shared config would produce unresolved-namespace noise in frontend packages.

## `backend/.clj-kondo/config.edn` (post-migration)

```clojure
;; Consume the shared law layer, then add backend-specific overrides.
{:config-paths ["../../kondo-config/clj-kondo.exports/open-hax/kondo-config"]

 :hooks
 {:analyze-call
  {knoxx.backend.macros/defroute hooks.defroute/defroute}}}
```

The `:config-paths` entry is merged *before* this local file, so everything in the shared package is inherited automatically. You only list what is genuinely local. 

## Any frontend package

```clojure
;; packages/frontend/.clj-kondo/config.edn
{:config-paths ["../../kondo-config/clj-kondo.exports/open-hax/kondo-config"]}
```

One line. Gets every promise-chain, fn-length, complexity, file-length, and discouraged-var rule for free.

## Migration checklist

1. Create `packages/kondo-config/` with the layout above
2. Copy `hooks/defroute.clj` and `hooks/promise_chain.clj` verbatim into the export subtree
3. Write the new shared `config.edn` (no `imports/`, no `defroute` hook)
4. Replace `backend/.clj-kondo/config.edn` with the two-key version above
5. Verify `backend/` still lints clean: `clj-kondo --lint src --config-dir .clj-kondo`
6. Leave `backend/.clj-kondo/imports/` untouched — it is per-package resolved analysis, not shared config 
7. For each new CLJS package, add `.clj-kondo/config.edn` with only the `:config-paths` line

The key invariant: `imports/` is always local, hooks files always live inside the export tree alongside the `config.edn` that references them, and backend-domain hooks stay out of the shared layer.
